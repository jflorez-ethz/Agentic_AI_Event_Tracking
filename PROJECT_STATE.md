## MVP and architecture

The primary workflow starts from a prerecorded, single-camera video. It ingests the source, extracts timestamped observations, investigates and verifies candidate events, reconstructs a chronological timeline, and renders an evidence-grounded report. Natural-language questions are optional follow-ups that retrieve stored evidence and can request bounded source-frame inspection.

The course project requires three distinct roles. Investigation selects and delegates evidence. Verification assesses candidate claims and requests complementary evidence when needed. Reporting chooses a supported lead and emphasis while Python renders factual content, citations, and uncertainty from validated records. Keep their decisions, tool calls, handoffs, and outcomes observable.

| Component | Current implementation |

| [Observation interface](src/security_augmented/observation.py) and [Gemini adapter](src/security_augmented/gemini.py) | Structured evidence-linked observations from timestamp-labeled PNG frames or verified silent WebM clips. The adapter uses the Google GenAI SDK. |

## Design decisions to preserve

- Source-relative times are integer microseconds and intervals are half-open. Preserve original frame PTS, rational time base, source hash, and display index. Equal PTS can identify distinct frames, so retain display order. Clip-relative citations resolve through a per-frame source map.
- The model may propose typed actions. Python controls tool execution, authorization, budgets, citation validity, and final factual rendering. The graph owns retrieved evidence and task state in graph mode. The runtime owns counters and trace records. Hosted tracing is disabled for graph execution.
- Positive corroboration in model-guided verification requires an explicit same-event assessment, exact excerpts from both descriptions, a shared cited source frame, and new source frames from a separate inspection. Category and time overlap alone cannot establish the same physical event. Archive lookups distinguish covered intervals with and without findings, partial coverage, missing coverage, and failures. Citations that straddle the requested lookup interval are excluded from that result.
- Reporting distinguishes intentional empty delegation from failure and accepted unresolved verdicts from unfinished checks. A later failure preserves earlier supported findings. Placement does not establish abandonment, unattended duration, intent, ownership, or later removal.
- The video-first CLI defaults to Gemini 3.6 Flash with HIGH thinking for all four model roles. Video Perception, Verification, and Reporting use an 8192-token output ceiling. Investigation uses 20480. Configure model IDs independently with `GEMINI_INVESTIGATION_MODEL`, `GEMINI_VERIFICATION_MODEL`, `GEMINI_REPORTING_MODEL`, and `GEMINI_VIDEO_MODEL`. The archive-only role evaluator has separate defaults. Existing experiment manifests retain their original settings.
- Direct visual findings, including person visibility, movement and `person_fell` (upright before, lying on the floor after), use a model-assessed ordered pair of cited source frames. A person-entry candidate can only be refined to `person_appeared` or `person_moved`, never to a fall. Verification can explicitly refine a person-entry candidate to a narrower visual claim. Physical entry requires corroboration and a grounded physical boundary. An image edge establishes a visibility boundary.
- Investigation must delegate or associate every visible security-relevant observation (all event categories except `person_moved` and `person_appeared`) before giving a candidate slot to routine activity or a relational task. All such observations are always visible to it. A first violation returns structured feedback for one new decision; a repeated violation, or too few remaining calls, makes the runtime displace routine candidates and log `priority_enforced`. Introduced after the live LeftBox run deferred the box placement in favour of four movements ([run](experiments/leftbox_live.qyrM8F/run/report.md), [fall run](experiments/fall_live.spFaYl/run/report.md)).
- An inspection rejected before dispatch (for example `no_new_frames`) has its own feedback round (`Budget.max_rejection_recoveries`, default 1), separate from the missing-corroboration recovery. For `no_new_frames` the feedback says how to obtain new frames (250 ms over at most five seconds, or a shifted interval). For physical-action candidates, Verification's context states `new_frames_at_500ms_in_citation`. Investigation sees `Budget.max_visible_observations` initial observations (default 8 for archived replays; the video-first CLI uses 16, `--max-visible-observations`). Each live role call archives the returned decision (`decision`, or `raw_text` when it is not JSON); the one-send Investigation diagnostic still stores no decision text. Context: the post-priority LeftBox run delegated the box, but its 500 ms corroborating inspection added no frames and ended the check ([run](experiments/leftbox_live.1iXjTj/run/report.md)). The Investigation-only replay delegated the box and the fall 3/3 each, directly from the prompt ([results](experiments/investigation_priority_replay/live-20261124T002515/results.json)). Open: direct visual verdicts sometimes return `insufficient`/`unsupported` with an affirmative reason (about 3 of 34 archived); diagnose from the newly archived decisions before changing the schema.
- Investigation accounts for initial observations through delegation, association, deferral, or justified exclusion. The report distinguishes triage coverage, completed checks, and overall investigation status. The live CLI exposes bounded initial sampling and agent budgets and saves effective settings, coverage and request limits.
- Keep archives read-only. Obtain explicit authorization before any external transfer. The archive-only hosted evaluation sends role prompts and derived observation text, IDs, intervals, and tool results. Its tools read the local archive and never invoke video perception or send media.

## Verified workflow and remaining limits

- The video-first CLI runs Perception, Investigation, Verification, and Reporting without a question. It writes `analysis.json` and `report.md`. Questions run locally afterward. Use the ordinary CLI with `--saved-analysis` to query a completed or partial saved run. This does not resume agent execution. The [isolated Verification runner](experiments/meet_walk_split_high_probes/verification-evaluation.md) replays the archived handoff through production validators and LangGraph, skips initial perception, and sends only separately authorized role text and requested targeted media. Its original mode replays Investigation. The independent-task option runs Investigation live over the same archived scan.
- Investigation's schema restricts observation identifiers to the current visible set. Associated dispositions require a same-event assessment with a shared frame. Runtime checks still enforce exact quotes, valid IDs, candidate membership, the four-candidate limit when configured, and the actual frame intersection. The [correspondence audit](experiments/meet_walk_split_high_probes/correspondence-audit.md) distinguishes shared visibility from event identity.
- [Event-relative retrieval](docs/event-relative-retrieval.md) resolves a unique, cited, supported lexical anchor for before, during or after. It returns supported and unresolved records separately. Before and after exclude overlapping brackets. During requires containment. Temporal succession cannot establish identity. A supported typed relation can anchor a relationship query in the opt-in workflow. The [approach audit](experiments/meet_walk_split_high_probes/approach-anchor-audit.md) explains why the archived diagonal-movement verdict alone cannot anchor that query.
- [Reporting](experiments/meet_walk_split_high_probes/report-specificity.md) preserves the deterministic category, verdict, timestamps and citations, and adds the retained supported rationale as an explicitly attributed model assessment. The Event has no per-detail verification status. A rationale can contain additional interpretation or mention an inspection omitted from the final verdict citations.
- WalkSplit evaluations explicitly use a 500 ms step, nominal 2 FPS. The general video-first CLI now defaults to 500 ms and the initial-scan guard rejects steps below 500 ms. The [matched sampling audit](experiments/meet_walk_split_high_probes/sampling-live.4GdQOj-audit.md) compared 30 and 60 frames over the same interval. Dense sampling cost 65,038 vs 32,618 prompt tokens and did not establish identity continuity or later divergence. The [adaptive pilot](experiments/relational_motion/inspection-pilot.md) narrowed the local overlap bracket from 480 ms to 240 ms without changing a relational verdict. Verification can now request a targeted 250 ms frame inspection in the production graph, once per task with a visual question, at most five seconds and twenty unique frames. The initial scan remains at 500 ms. Adaptive selection has been exercised with offline model responses. The [first end-to-end run audit](experiments/mvp_live.UAJd48/audit.md) covers the earlier fixed-step execution.
- The [relational contract](experiments/relational_motion/integration.md) separates apparent image-plane convergence, nearby visible people, local divergence, and same-pair separation. The [autonomous mode](experiments/relational_motion/autonomous-discovery.md) uses targeted frame perception without prepared reviews. Verification can select a proposal, and LangGraph validates and retains it separately from the movement verdict. Autonomous proposals exclude same-pair separation and `distinct_paths`. The low-level distinct-path check depends on a visual judgment supplied as a boolean, which can pass even with stationary marks.
- The [inspection-selection mode](experiments/relational_motion/inspection-selection.md) supplies up to four overlapping archived inspection leads and requires a concrete visual question for a relational inspection. That question now reaches Perception as an unverified lead at both 500 and 250 ms; before 2026-11-23 it was forwarded only at 250 ms. An inspection lead retains its disposition and sits outside the individual verdict evidence.
- The production video CLI enables independent tasks by default and offers `--movement-only` for comparisons. The [independent-task mode](experiments/relational_motion/independent-tasks.md) lets live Investigation optionally assign an open-ended relation task over two or more existing observation IDs. Runtime derives source and scope from citations, deduplicates task IDs, and enforces a shared four-slot budget in the WalkSplit runner. Movement and relation completion are separate. Supported relations retain provenance through Event, Reporting, and typed event-relative retrieval. There is no negative relation outcome in the pilot. Missing proposals and insufficient evidence leave the task unresolved.
- The [Investigation schema audit](experiments/meet_walk_split_high_probes/investigation-400.md) recovered Gemini's HTTP 400 explanation that the structured-output grammar had too many serving states. The opt-in provider schema omits the task-list maximum and task observation-list minimum. Runtime still enforces both requirements and validates IDs, citations, and scope. The [isolated provider check](experiments/meet_walk_split_high_probes/investigation-schema-bounds-check-live/result.json) returned HTTP 200, STOP, and a runtime-accepted `delegate`. It did not retain the decision body. The subsequent full run saved the actual decision and confirmed that the revised schema was accepted on that trial.

## Resume safely

Use Python 3.12+, FFmpeg/ffprobe, and FFmpeg with `libvpx-vp9` for the Gemini clip path. In a virtual environment, install development and optional graph dependencies with `pip install -e '.[dev,graph]'`. The most recently verified graph environment used LangGraph 1.2.14 and Google GenAI SDK 3.6.1. Default pytest discovery excludes `tests_live/`.

```sh
.venv/bin/python -m pytest -q

.venv/bin/python -m security_augmented.agent_eval data/raw/LeftBag.mpg \
  --archive experiments/e1_comparison_001 \
  --archive experiments/e1_comparison_001_a_clip_retry_001 \
  --output /tmp/leftbag-state-check \
  --scripted-recovery
```

Use a fresh output directory. The scripted command sends no data and compares deterministic, original Python, and StateGraph outcomes from the same seven attempts. The baseline workflow and follow-up CLI are described in the [progress log](docs/progress.md#video-first-offline-vertical-slice).
