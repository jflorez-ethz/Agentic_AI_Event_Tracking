# D3 and D5: Review Step, Audit Log and Incident Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep every agent run reviewable. Add a terminal review step in which a person approves or dismisses each alert, with an append-only audit log and an override rate. Draft an incident report for any approved alert, checked against the evidence.

**Architecture:**
- `evaluate.py` keeps each agent run's alert store, evidence copies and audit log in its run folder.
- `agentlab/audit.py` owns the audit log and the run folders.
- `agentlab/actions.py` maps event types to the procedures' actions.
- `agentlab/review.py` and `review.py` hold the review logic and its terminal screen.
- `agentlab/report_writer.py` and `report.py` collect the facts, draft the report with Haiku, check it and render it.

**Tech Stack:** Python ≥3.11, pydantic-ai-slim[anthropic] 2.x, ffmpeg, pytest. Everything is already installed.

**Spec:** `docs/design/2026-11-21-d3-d5-review-and-reports-design.md` (approved 21 Nov, with the details decided at its end).

**Where work happens:**
- Claude Code builds on the Mac, in plan mode first. Claude in the project chat reviews each batch.
- The user runs the paid demo.
- There is one commit per task: `d3d5 task N: <what>`.

## Global Constraints
- Tests never call a real model API: `pydantic_ai.models.ALLOW_MODEL_REQUESTS = False` in every new test module. The builder never opens `.env`.
- Do not change `app.py`, `run_replay.py`, `scripts/compare_models.py`, `agentlab/scoring.py`, `agentlab/triage_agent.py` or `fakecctv/alerts.py`. Use `AlertStore` as it is.
- The audit log is append-only: never rewrite or delete a line of `audit.jsonl`.
- The reviewer defaults to `"Guard on duty"`. No personal names are needed anywhere.
- No action is logged without an `approve` decision. `dismiss` and `reopen` need a non-empty reason.
- Every model call is logged with `agentlab.usage.log_call`.
- Report model: `anthropic:claude-haiku-5-5`, built with `defer_model_check=True`, with no sampling settings.
- Alerts can be named by alert id (`A-012`) or candidate id (`CAM-05-1`).
- All 75 existing tests keep passing. The stub path of `evaluate.py` is unchanged.

## Review Focus
1. **A run folder from before D3 has no `alerts.jsonl`.** `review.py` and `report.py` stop with "This run folder has no alerts.jsonl; it was made before the review step. Run evaluate.py --triage agent again." Test in Task 3.
2. **An evidence file is missing** (the temporary folder was cleaned). `keep_evidence` skips it, and the report says "evidence clip missing" with no still frame. Tests in Task 1 and Task 5.
3. **Re-running the scripted demo decides the same alert twice.** The second decision is refused with "A-012 was already decided (approve)." and no audit line is added. Test in Task 3.
4. **`--run latest` when `runs/triage/` also holds repeat folders and JSON files.** It picks the newest directory that contains `alerts.jsonl`. Test in Task 3.
5. **The report draft uses a time like "1:58 pm" or "13:58".** "13:58" is matched against fact minutes; am/pm times are flagged "time not in site format (HH:MM:SS)". Test in Task 4.

### Task 3: Review step and audit summary (D3)

**Files:**
- Create: `agentlab/review.py` (logic) and `review.py` (CLI, kit root)
- Test: `tests/test_review.py`

**Interfaces:**
- Consumes: Task 1 (`append`, `read`, `resolve_run_dir`), Task 2 (`proposed_action`) and `AlertStore(run_dir)`.
- Produces, in `agentlab/review.py`:
  - `find_alert(alerts: list[dict], ref: str) -> dict`: by alert id or `candidate.candidate_id`. Raises `ValueError(f"No alert {ref} in this run.")`.
  - `pending(run_dir) -> list[dict]`: escalated alerts with no decision in the audit, ordered high, medium, low, then by `created`.
  - `closed(run_dir) -> list[dict]`: `dismiss` and `linked` alerts with no decision in the audit.
  - `decide(run_dir, ref, decision, reason="", reviewer="Guard on duty") -> dict`:
    - `decision` ∈ {approve, dismiss, confirm, reopen}. approve and dismiss are only for escalated alerts; confirm and reopen only for agent-closed ones. Otherwise it raises `ValueError` naming the alert's verdict.
    - dismiss and reopen without a reason raise `ValueError("A reason is required to dismiss or reopen.")`.
    - A second decision raises `ValueError(f"{alert_id} was already decided ({decision}).")`.
    - It writes `AlertStore.decide(alert_id, decision, site_time=datetime.fromisoformat(alert["created"]), note=reason)` and an audit entry `{"type": "decision", "alert_id", "candidate_id", "decision", "reason", "reviewer", "alert_site_time": alert["created"], "agent_verdict", "agreed"}`.
    - `agreed` is True for approve and confirm, False for dismiss and reopen.
    - On approve, it also appends `{"type": "action", "alert_id", "action": proposed_action(kind, zone), "approved_by": reviewer}`.
    - It returns the decision entry.
  - `summary(run_dir) -> dict`, with keys `alerts, escalated, closed_by_agent, decisions, approved, dismissed, confirmed, reopened, overrides, override_rate, actions, reports`. `override_rate = overrides / decisions` rounded to 3 places, or `None` with no decisions.
  - `render_alert(alert, color: bool) -> str`, using the layout in the spec's "Details decided" item 1. When `color` is true, the priority word gets ANSI red, yellow or dim.
- CLI `review.py`:
  - `--run DIR|latest` (required);
  - `--closed`;
  - `--decide REF=approve|confirm|dismiss:REASON|reopen:REASON`, repeatable, non-interactive;
  - `--reviewer`;
  - `--summary`.

  Interactive keys: `a`, `d` (asks for a reason), `o` (opens the first evidence file with `open` on macOS or `xdg-open` otherwise, without waiting), `s`, `q`. In `--closed` mode the keys are `c` and `r`. Colour only when `sys.stdout.isatty()` and `NO_COLOR` is unset. Each decision prints `decided <HH:MM> (real time) for the alert first seen <HH:MM:SS> (site time)`.

### Task 4: Report facts and the checker (D5, no model)

**Files:**
- Create: `agentlab/report_writer.py` (the facts and check parts)
- Test: `tests/test_report_writer.py`

**Interfaces:**
- Consumes: the run folder (`alerts.jsonl`, `<candidate_id>.json` run files, `audit.jsonl`) from Tasks 1 to 3.
- Produces:
  - `collect_facts(run_dir: Path, ref: str) -> dict`, with keys:
    - `site, alert_id, candidate_id, camera, zone, kind, first_seen, detected_at, created` (site times `HH:MM:SS`);
    - `verdict, priority, reason, linked_to, evidence` (relative paths);
    - `video_events`: a list of `{time, end, type, real, what, model}`, in site times. Each successful `ask_video` or `second_look` is mapped to the clip start of its `get_clip` (by `clip_path`), or to `second_look`'s own `start`, plus `start_s` and `end_s`;
    - `context`: a list of `{source: "access_log"|"roster", text}` from successful results;
    - `decision` (the audit decision entry or None) and `action` (text or None);
    - `fact_times`: a sorted list of every `HH:MM:SS` above.
  - `check_report(texts: list[str], facts: dict) -> list[str]`, which flags:
    - every `HH:MM:SS` not within 2 s of a fact time;
    - every `HH:MM` not matching a fact time's minute;
    - every am/pm time, as "time not in site format (HH:MM:SS)";
    - every `CAM-\d+` other than the facts' camera and the camera of `linked_to`;
    - these words, whole word and any case: man, men, woman, women, male, female, boy, girl, lady, ladies, gentleman, guy, he, she, him, her, his, hers, elderly, teenager, child, children, kid;
    - these filler phrases, any case, as "filler phrase: ...": "it is worth noting", "it should be noted", "it appears that", "in conclusion", "overall,", "notably", "seamless", "robust", "delve".

    Each flag is one sentence naming the text found.

### Task 5: Report drafting, still frame and `report.py` (D5)

**Files:**
- Modify: `agentlab/report_writer.py` (draft, still and render parts)
- Create: `report.py` (CLI, kit root) and `context/report_template.md`
- Test: `tests/test_report_writer.py` (more tests)

**Interfaces:**
- Consumes: Task 4 (`collect_facts`, `check_report`), Task 1 (`append`, `resolve_run_dir`) and `log_call`.
- Produces:
  - `class TimelineEntry(BaseModel)`: `time: str`, `what: str`.
  - `class ReportDraft(BaseModel)`: `title: str`, `summary: str`, `timeline: list[TimelineEntry]`, `context_checked: list[str]`, `action_taken: str`, `open_points: list[str]`.
  - `build_writer(model: str = "anthropic:claude-haiku-5-5") -> Agent[None, ReportDraft]`:
    - built with `defer_model_check=True` and no tools;
    - its instructions say:
      - use only the facts given;
      - times only from `fact_times`, as `HH:MM:SS`;
      - "a person", never gender, age or ethnicity;
      - a summary of 2 to 4 short sentences in plain words: what happened, where, when and what was done;
      - each timeline line is one event at one site time;
      - no filler, hedging or praise (the checker's filler list);
      - no guesses beyond the facts: anything unknown goes under Open points.
  - `still_frame(run_dir: Path, facts: dict) -> str | None`:
    - the time is the first `video_events` entry of the alert's own type (real first), else `first_seen`;
    - the source is the evidence clip of the alert's camera whose window covers that time;
    - ffmpeg writes `evidence/<candidate_id>/still.jpg`;
    - it returns the relative path, or `None` when there is no clip.
  - `render_markdown(facts: dict, draft: ReportDraft, flags: list[str], still: str | None) -> str`:
    - it fills `context/report_template.md` with `str.format` named fields;
    - the header table comes from the facts only;
    - the sections and their order are those in the spec's "Details decided" item 2;
    - Checks reads "All times and cameras match the evidence." or lists the flags;
    - Evidence lists the relative paths, or "evidence clip missing";
    - the footer reads "Draft: needs sign-off by the reviewer."
  - `write_report(run_dir: Path, ref: str, *, writer=None, model: str = "anthropic:claude-haiku-5-5", force: bool = False) -> Path`:
    - it refuses with `ValueError(f"{alert_id} is not approved; approve it in review.py first, or use --force.")` unless an approve decision exists;
    - it writes `reports/<alert_id>.md`;
    - it calls `log_call(provider="anthropic", model=<id>, ..., tag=f"report:{alert_id}")`;
    - it appends `{"type": "report", "alert_id", "path", "model", "cost_usd", "seconds", "flags"}`.
  - CLI `report.py`: `--run DIR|latest`, `--alert REF`, `--force`, `--model`. It loads `.env` by path with `override=True` and strips the key, as `evaluate.make_agent` does, and prints the path, the flags, the seconds and the cost.
