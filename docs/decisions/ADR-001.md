# ADR-001: Bounded multi-agent video investigation

- **Status:** Selected direction for preparation; implementation and empirical validation pending.
- **Date:** 2026-11-20
- **Context:** A university MVP must implement timestamped video-to-text, chronological event reconstruction, natural-language video retrieval and evidence-grounded reporting, with integrated alert verification and meaningful multi-agent coordination. It must remain traceable to prerecorded footage and feasible within course constraints.

## Decision

The primary trigger is video upload. Initial observations start investigation, verification, reconstruction and reporting automatically. Questions are a secondary workflow over existing evidence and bounded targeted inspections.

Use one Python application and a deterministic, budgeted state machine coordinating three specialized model-driven roles: investigator, verifier and reporter. Use deterministic functions for ingestion, decoding, timestamp mapping, search, sorting, schema/reference checks and rendering. Share versioned evidence records and explicit IDs. Verification can request additional source inspection, preserve contradictory evidence, and return insufficient evidence. Source footage is read-only and citations resolve to original video and actual inspected timestamps.

Select FFmpeg/ffprobe for the initial video experiment and SQLite with FTS as the initial storage/search direction. Use a replaceable multimodal adapter; the Google GenAI SDK and an accessible Gemini video/image-capable model are a candidate to test, not an assured model selection. Compare timestamped frames and clips when both are available. The proposed Python module contracts are in [architecture.md](../architecture.md).

## Decision status and evidence

The functional scope, mandatory multi-agent coordination and original-footage traceability are project requirements. The bounded three-agent and single-process design is the selected architectural direction from the council review. It is **not validated by implementation or user data**. FFmpeg and ffprobe were found installed in the current workspace environment; no source recording, Gemini API key or Google GenAI SDK was found during preparation. This does not establish model availability through every possible configuration.

The council's confidence-weighted vote did not reach its consensus threshold: lexical-first received 3.00 and compare-embeddings-before-commitment received 0.75, against 3.33 required. Lexical-first is the initial implementation direction, with the alternative retained as an experiment. No accuracy or cost improvement is assumed.

## Alternatives considered

| Alternative | Reason not selected initially | Tradeoff |
|---|---|---|
| Single model or fixed pipeline only | Does not demonstrate the required specialized multi-agent handoffs. | Simpler and retained as a matched-resource evaluation baseline. |
| Free-form peer-to-peer agents or agent framework | More orchestration and versioning without demonstrated MVP benefit. | May provide useful traces or flexibility later. |
| Vector database and embeddings as mandatory infrastructure | Extra dependency before retrieval need is measured. | FTS can miss paraphrases; test local embeddings on the same annotated queries. |
| Object detectors, tracking and identity components | Additional integration and unsupported identity/continuity assumptions. | May miss opportunities to improve perception; revisit only if a scoped experiment justifies it. |
| Local multimodal model as default | Available hardware, throughput and footage quality are unknown. | Avoids hosted transfer, but requires an actual feasibility comparison. |

## Open decisions and consequences

- Sampling interval, window overlap and clip versus frame input require the first experiment; sparse sampling can miss an event before any verifier sees it.
- Model provider, model ID, access, retention/transfer conditions, quality, latency and cost are unverified. Verify approved footage and credentials before any hosted submission.
- Choose lexical-only or local embeddings after independently labeled paraphrase testing. Neither retrieves events omitted by perception.
- Confirm taxonomy, project duration, resources and numerical success thresholds with the supervisor before held-out evaluation.
- SQLite schema/library versions, user interface and exact budgets remain implementation choices; avoid a new service without measured need.
- A second agent using the same model may share errors. Evidence links establish provenance, not truth; human review and a controlled baseline are necessary.

Revisit the direction if E1 cannot preserve replayable timestamps or the approved model cannot handle the recording within the agreed budget. See [implementation-plan.md](../implementation-plan.md) and [evaluation-protocol.md](../evaluation-protocol.md) for gates and procedures.
